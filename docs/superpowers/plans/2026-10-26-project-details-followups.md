# 项目型号规格与跟进记录实施计划

> 执行：superpowers:executing-plans，在本会话逐项落实原 PRD 已确认的项目明细与跟进要求。

## Goal

阶段 C 第一部分：同一项目下多型号、多规格分别报价和维护业务阶段，项目及明细都可追加业务跟进。

## Architecture / Tech Stack

Vue 3 新增独立项目业务详情弹窗，Spring Boot/JPA/H2 新增明细与跟进表，复用本周更新与公司变更记录。Flask 原表导入和导出保持原有数据结构，本轮不把旧报告行猜测合并成新明细。

## Spec

`docs/prd/客户与项目交易管理应用_PRD_v0.3.md` 的 BR-04至07、FR-P02至07、FR-F01至03及数据迁移要求；路线图阶段 C。

## Global Constraints / Rulings

- 基线 `7b987a5`；在 `codex/project-details-followups` 分支复用现有本地环境。
- 不扩展尚待确认的订单、交货、收款、报告四表导出和正式 EOL 判定。本轮保留已有报告，型号规格由用户确认后新增。
- 明细业务阶段使用 PRD 已列出的七种状态，空白表示未确认；不新增更细阶段或推断正式订单。测试阶段仍取项目原有 EVT/DVT/PVT。
- 型号和规格至少填一项；其他信息可留空。同一项目下相同型号加规格提示重复，不用名称充当内部编号。
- 金额与预测量使用精确十进制（最多13位整数、6位小数），接口输出字符串；币种、数量单位和计价说明独立保存，不自动计算营业额，不把未知记作零。
- 量产预估保留文本，允许日期、月份或季度；不将季度转换成某一天。
- 跟进必须填写发生日期、内容和资料来源，可关联项目整体或某条明细。可在追加跟进时同步更新该明细阶段，发生日期与系统记录时间分别保存；历史不覆盖。误录用新的更正跟进说明。
- 明细用归档/恢复代替删除；带有明细或跟进的项目禁止单项或批量删除，整批预先检查，避免孤儿记录。
- 用户本轮未要求测试/验收，遵循当前开发指令，不新增或运行测试。进行前后端构建、独立代码审查和页面布局查看，明确这些不等于完整业务验收。

## Review Focus

项目/明细归属校验、已归档明细限制、金额精度与空值、事务内同步更新及历史快照、旧数据兼容、项目删除保护、界面异步请求和重复提交。
