# 客户备案字段与长期交易条件

## Goal

继续已确认路线图阶段 B：客户信息只需建档一次，保存首次交易确定的收款、对账、开票条件，为后续订单和 Word 生成提供主档。

## Architecture / Tech Stack

保留 Vue 3、Spring Boot/JPA/H2、Flask 和海洋主题。客户基本字段保持兼容，新增受白名单约束的 profile 字段表，按客户编号保存。交易条件修改复用现有同事务变更记录，支持本周更新查看前后值。

## Spec

依据 `docs/prd/客户与项目交易管理应用_PRD_v0.3.md`、`docs/prd/客户表单填写区域与规则_v0.1.md` 和 `docs/开发进度与后续计划.md` 的阶段 B。

## Global Constraints / Rulings

- 客户全称仍是唯一必填项；资料未知保留空白，不将空白视为否、无或零。
- 收款条件包含预付款、货到付款、月结30/60/90/120/150/180天和其他约定；自由文字保存原意，信用额度保留金额及币种单位。
- 评级、审批、核准只提供人工录入，不自动评级、代签或默认通过。新增日期也不自动填今天。
- 不扩展资信表尚待确认的财务字段，不生成 Word，不创建订单；后续订单默认继承及历史快照留在阶段 C 实现。
- API 兼容旧客户端：省略 profile 保留原扩展资料；提交部分 profile 仅合并给定字段，空字符串清空该字段；拒绝未知键、超长和无效选项。
- 在新功能分支复用当前已安装依赖的工作目录，无需新建工作树。保持正式客户资料及数据库在 Git 忽略范围内。
- 遵循当前开发指令：用户未另行要求新增或运行测试，因此本轮不新增或运行测试；进行打包构建、代码检查与页面布局查看，并如实记录范围。
