# 客户表单填写区域与规则

版本：v0.1  
日期：2026年10月23日（北京时间）  
用途：作为客户与项目交易管理应用PRD的填写映射附件，指导后续模板准备、AI识别、自检和人工补填。

## 1 对照范围与结论

用户明确指定前两份为空白模板、后两份为已填样例。本附件按这两组文件对照，未修改任何原Word文件。

| 类型 | 空白模板 | 已填样例 |
| --- | --- | --- |
| 客户备案 | （本地路径已省略） | （本地路径已省略） |
| 客户资信 | （本地路径已省略） | （本地路径已省略） |

已填样例可以证明某个区域是录入位置，也能说明一次实际填表时哪些区域留空；它不能单独证明每个空白字段都免填，也不能证明填写值和勾选结论一定正确。

客户资信空白模板并非完全清空状态。正文中仍存在客户相关预填值、填表人和评估性文本。自动生成其他客户文件前，需要准备清理过且经确认的模板副本，不能把这些内容直接继承到新客户。

### 1.1 检查方法和边界

通过旧版Word文件的文本分段表读取当前正文，并将页眉页脚等其他文档故事与正文分开核对；四份文件均为单个正文文本片段。按字段标签比较模板与样例的差异。

本次是正文内容及字段差异检查，没有对Word页面进行渲染核验。因此，不将复选框最终显示状态、红色重点标记、签名图形、单元格精确边界和最终分页视为已经验证。正式模板生成前仍需做版式和选项的视觉核对。

### 1.2 文件里的业务说明与本次授权

原表中的填表说明、真实性承诺、每月评级说明等均作为被分析的业务内容。它们不构成用户要求助手自动修改评级、签署承诺、执行审批或安排定期任务的指令。

## 2 填写规则分类

| 分类 | 含义 | 自动填写原则 |
| --- | --- | --- |
| 有依据的客户字段 | 模板标签对应客户真实信息 | 只使用该客户提供或用户确认的来源，填后核对 |
| 公司和经办配置 | 我司交易主体、经办业务员等 | 使用经用户确认的当前配置，不复制客户样例里的值 |
| 条件性字段 | 变更内容、特殊注册资料等 | 满足适用条件后填写；条件不明确则保留空白并询问 |
| 勾选项 | 是/否、有/无、付款条件、资本性质等 | 有证据才选择；未知不能默认选择否或无 |
| 评估和审批区域 | 客户评级、经营评价、签字、核准等 | 不由AI自行作结论；需要有授权依据或人工完成 |
| 固定表单内容 | 标题、标签、说明、选项文字等 | 保持格式，不当作客户填写值；异常旧公司落款需单独确认 |
| 模板遗留内容 | 空白模板中已存在的客户值、旧经办人或预选项 | 不视为默认值；先清理或确认再生成客户文档 |

## 3 客户资料备案表

### 3.1 样例能够证明的填写位置

| 字段 | 对照观察 | 后续填写规则 |
| --- | --- | --- |
| 我司交易抬头 | 空白模板留空，样例填入我司公司名称 | 从确认的我司交易主体配置带出，不能固定为样例值 |
| 客户名称 | 样例新增客户全称 | 按合同、执照或用户明确提供的正式名称填写 |
| 所属行业 | 样例新增行业 | 资料明确才填，不靠公司名称推测 |
| 地址 | 样例新增地址 | 核对是所需客户地址，和资信表注册地址不自动视为同一个地址 |
| 电话 | 样例新增固定电话 | 保留号码准确性和区号，不复制其他客户号码 |
| 联系人 | 样例新增联系人 | 结合截图身份核对，不能把发送截图的人直接当作客户联系人 |
| 邮箱 | 样例新增邮箱 | 核对拼写、所属客户和联系人 |
| 手机号 | 样例新增手机号 | 按有依据的信息填写，缺失留空 |
| 需求产品 | 样例新增具体产品型号 | 可以多项，保留型号字符；不代表每个后续订单均相同 |
| 客户月用量 | 样例填写带周期与单位的月需求 | 同时核对数值、单位和周期，不统一换算成台或实际订单量 |
| 交易方式 | 样例新增双方约定的交易表述 | 根据首次约定或后续正式变更填写，不套用其他客户条款 |
| 对账周期 | 样例新增对账频率 | 按约定填写，不由付款账期自动反推 |
| 开票日期 | 样例新增相对月份的开票规则 | 保存规则原意，不强行转换为某个固定日期 |
| 对账日期 | 样例新增每月截止规则 | 保留截止日语义，避免与付款到期日混淆 |
| 业务员及日期 | 样例新增经办人和日期 | 经办人须确认；日期按实际建档业务填写，不能复用样例日期 |

### 3.2 仍是填写位置但样例未明确填入的字段

| 字段或区域 | 对照观察 | 暂定处理 |
| --- | --- | --- |
| 建档类型 | 提供新建客户、客户信息变更选项；文本对照不能可靠确认显示勾选状态 | 由本次任务确定类型，并在正式模板阶段检查勾选效果 |
| 变更内容 | 样例为空 | 信息变更时按事实填写；新建客户时的免填规则为条件性判断 |
| 传真 | 模板和样例均为空 | 属于可填写字段；是否可长期免填未确认 |
| 收款条件选项 | 有预付款、货到付款及多种月结选项 | 根据真实约定选择；文本交易方式与勾选不得冲突 |
| 信用额度 | 模板和样例均为空 | 需要批准或约定依据；未知留空，不写0替代未知 |
| 其他 | 模板和样例均为空 | 有额外真实约定时填，没有依据不编写 |
| 是否含税 | 有是/否选项 | 以实际交易约定为准，不能从税率或样例推断 |
| 法人身份证复印件情况 | 有有/无选项 | 核实实际资料状态；没有看到文件不等于客户没有提供 |
| 客户等级 | 模板和样例均为空 | 由用户或相应评估流程给出，AI不自行评级 |
| 是否签订正式合同 | 有是/否选项 | 按合同签订事实选择，不能以存在订单代替合同结论 |
| 营业执照复印件情况 | 有有/无选项 | 按真实已收资料确认 |
| 客户类型 | 有新开发客户、公司分配客户选项 | 用户确认客户来源后选择 |
| 审批及日期 | 样例为空 | 保留人工审批区域，不代签、不自动填已审批 |
| 核准及日期 | 样例为空 | 保留人工核准区域，不代签、不自动填已核准 |

样例中的空白只代表该文件未显示填写，不能作为公司正式免填规则。

### 3.3 固定内容与重点标记

固定表单内容包括标题、版本号、流程一至四的说明、字段标签、复选项文字及表尾备注。保留这些内容，但不能把备注当作当前用户的执行指令。

文本中带星号的字段包括我司交易抬头、建档类型、客户月用量、收款条件、对账周期、开票日期、对账日期和客户类型。模板备注同时写有原则上信息均需填写完整，标红点为重点信息。这些是表单说明，不等于已经得到用户确认的应用必填校验规则；红色范围和最终必填项还需核对。

## 4 客户资信调查表

### 4.1 样例能够证明的新增填写位置

| 字段 | 对照观察 | 后续填写规则 |
| --- | --- | --- |
| 客户名称 | 样例新增客户全称 | 与客户备案表核对主体一致 |
| 组织代码 | 样例新增识别号码 | 根据原始证照核对，不自动等同或更正为营业执照号码 |
| 注册地址 | 样例新增地址 | 使用登记注册地址；与联系地址可能不同 |
| 邮政编码 | 样例新增邮编 | 有来源再填，不按城市随意推断 |
| 联系电话 | 样例新增固定电话 | 与相关来源核对，必要时区分不同部门电话 |
| 客户所属行业 | 样例新增行业 | 可与备案表复用已确认的同一字段 |
| 客户资本性质 | 样例改变自然人选项的文本标记 | 只能据明确资料选择；样例勾选不能成为新客户默认值，也不证明该分类结论适用于其他客户 |
| 主营业产品 | 样例新增客户主营产品说明 | 描述客户主营业务，不能自动填成我方向其销售的材料型号 |
| 资信状况部分的注册资本 | 样例在第一处注册资本填写金额文字 | 保留原始单位和表述；转换为万元数值时需校验，不自动同步到其他注册资本位置 |
| 注册资料部分的营业执照号码 | 样例新增证照号码 | 与原始证照核对，并与同表组织代码做一致性检查 |

### 4.2 样例留空的资信填写位置

以下字段仍是填写区域。是否需要每次填写或是否适用，不能只依据这份样例判定。

| 字段组 | 字段 | 暂定处理 |
| --- | --- | --- |
| 联系与经营 | 传真、设备状况、主要收入来源 | 有资料则填写，缺失留空待补 |
| 供应商与历史 | 目前主要供应商及付款情况、历史交易及债务逾期诉讼说明 | 需要用户或对应调查材料确认；未知不能写无 |
| 同行评价 | 公司整体方面、货款支付方面 | 不由AI生成未经证实的评价 |
| 资产与需求 | 厂房及土地使用情况、总资产、可抵押固定资产、月平均收入、产品年采购需求 | 必须区分单位与统计期间，不从样例或公司规模推测 |
| 注册资料 | 注册机关、该部分的注册资本、税务登记号、财务负责人、营业期限、最新注册日 | 先判断适用主体；相关部分可能针对挂靠或担保企业，不能全部照搬客户主体资料 |
| 主要财务数据 | 年销售收入、年利润、流动资产、净资产、应收账款、存货、负债总额、流动负债 | 表头单位为万元；来源、期间和口径不明则留空，不填0表示缺失 |
| 银行信息 | 银行地址、银行信用评级 | 按实际资料填写；不能自行给信用等级 |
| 经办与审批 | 填表日期、总经理审核 | 日期需明确；审核区域交人工授权流程完成 |

### 4.3 名为空白模板但含有预填内容的区域

以下结论已通过当前正文文本确认，不依赖删除历史或旧缓存文本。

| 区域 | 观察 | 新客户文档规则 |
| --- | --- | --- |
| 法人代表 | 所称空白模板已预填具体姓名，已填样例中相同 | 属于客户相关数据，不能作为模板固定文字继承 |
| 开户银行 | 所称空白模板已预填具体银行支行 | 先清理，再按新客户实际开户资料填写 |
| 账号 | 所称空白模板已预填具体账号 | 不复制、不作为默认；缺失时保持空白 |
| 填表人 | 所称空白模板已预填具体经办人姓名 | 与当前用户或经办人核对，不自动沿用 |
| 目前经营状况 | 所称空白模板已写有良好，样例未变 | 属于评估内容，不是固定标签；需要来源支持，不能一律继承良好 |
| 资信资料来源 | 所称空白模板在客户提供选项处已有实心方块文本 | 重新核对资料来源，不能视为永久预选；正式显示状态另需视觉检查 |

这些值的存在不代表用户要求保留它们。正式使用前应制作经确认的清理副本，原文件保持不变。

### 4.4 固定文字与待核对元数据

标题、分组名称、字段标签、计量单位、选项说明和真实性承诺正文属于表单固定内容。真实性承诺保留文本不代表AI替用户签署。

模板的其他文档故事中包含公司落款、管理程序名称、旧编号和实施日期等内容，且出现与客户备案表交易主体不同的公司名称。这些属于模板适用性待核对项，不自动当作当前业务的正确公司落款，也不擅自删除。

## 5 样例本身需要自检的内容

1. 已填资信表的组织代码与营业执照号码文本不一致，字符长度也不同。只能标为待核对，不能猜测哪个正确或自行改写号码。
2. 一处注册资本有值，另一处注册资本为空。两处可能描述不同主体，不以同名字段为由自动互相覆盖。
3. 联系地址与注册地址分别保留，虽然样例相近，也不能保证新客户相同。
4. 样例里的经营评价、资本性质和资料来源不等于已经过助手核实的事实；新客户必须使用自己的来源。
5. 备案表备注的重点或完整填写要求与样例留空同时存在。最终免填项应由用户或公司流程确认，不能由差异比对直接决定。

## 6 后续自动填写流程

1. 选择经确认的模板版本，检查是否仍有旧客户个人、企业或银行信息。
2. 从当前客户资料提取数据，保留来源，区分客户信息、公司配置和评估审批项。
3. 将有证据的数据填写到对应位置；固定标签和表格结构保留；条件和未知项保持空白。
4. 助手自检客户主体、证照号码、联系方式、金额单位、账期规则、重复字段与旧值残留。
5. 将缺失、冲突和适用性问题列为待补清单，一次询问用户一个问题；由用户补充或手动填写。
6. 在正式生成时核对勾选、红字、格式及分页。没有完成视觉检查时不声称已保持原表版式。
7. 按用户要求归档到桌面对应客户文件夹，保留模板和旧版本；用户直接在Word补填后的数据同步方式另行确认。

## 7 已确认和仍待确认

**已确认的用户要求**：AI识别填写后自检，不确定项留空询问，由用户手动补填，文件放到桌面对应客户文件夹。用户已经提供两份模板及两份已填样例。

**本次可以确认的文件事实**：上述已填位置、样例空白位置、资信模板预填内容以及样例证照号码不一致。

**仍待确认的业务政策**：样例留空字段是否正式免填；星号和红字是否作为应用强制校验；银行与经办人预填值的清理确认；资信字段是否全部入库或只生成文件；模板公司落款；人工补填入口及回写方式。

后续开发不得将这些待确认政策伪装为已经由用户确认的要求。
