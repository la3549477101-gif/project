## 1. 项目定位

这是一个供个人本机使用的 ODM 项目、客户与交易跟踪工具。目前没有部署云端服务，也没有跨电脑同步业务数据库。

- 前端：Vue 3 + Vite。
- 主数据服务：Spring Boot + H2 文件数据库。
- 导入、统计与导出服务：Flask，通过 HTTP 调用 Spring Boot。
- GitHub Public 仓库存放源码和已脱敏文档，不存放客户/项目数据库、客户文件、API 密钥或运行日志。

## 2. 已完成并可用

### 项目跟踪基础版

- 新增公司工作台：按固定客户编号集中查看所属项目和变更记录；客户基本资料包含全称、简称、联系人、联系方式和备注。
- 新建客户后自动创建桌面客户文件夹并显示结果，失败可重试；客户改名保留原目录。
- 新增客户备案资料：我司交易抬头、建档类型、行业、联系地址、电话、传真、邮箱、手机号、需求产品和月用量等；分组编辑、分组查看，可后续补填。
- 新增长期交易、收款、信用额度、对账、开票、含税条件；资料状态和人工经办审核栏均可留空，评级和审批不自动生成。
- 客户新增资料逐字段记录变更前后值，进入现有本周更新；重复保存相同内容不新增修改记录。订单确认时自动保存客户条款历史快照。
- 项目列表新增“规格与跟进”：同一项目可保存多个型号规格，分别记录报价、币种、单位、预测用量、量产预估文本和业务交易阶段；原项目测试阶段独立保留。
- 项目整体及具体明细可追加业务跟进，保留日期、来源、下一步计划和下次跟进日期；字段变更、归档和恢复也进入项目历史及本周更新。
- 明细支持归档与恢复。带有明细或跟进历史的项目禁止直接或批量删除，防止丢失关联资料。
- 左侧新增“本周更新”，按北京时间周一至周日查看新增和实际修改，保留变化摘要、历史快照和公司筛选。
- 旧项目保持未归属，可在列表勾选后手动归属公司；不会根据终端客户或ODM字段猜测采购公司。

- 新增、编辑和删除项目；支持列表搜索、阶段筛选、统计卡片。
- 项目字段包括终端客户、ODM 集成商、模组厂、项目名称、应用、测试阶段、测试阶段需求数量、项目预计总需求量和预计 MP 日期。
- 列表支持勾选当前显示项目并批量删除；删除前会确认。
- EVT、DVT、PVT、MP、ODM、CSV 等常见缩写在界面中附有中文说明。
- 页面沿用海洋主题，按2026-10-26最新参考改为水下光束背景、通透蓝色面板、浅色文字和清晰分界线。
- 项目表格固定左侧勾选框、采购客户公司、项目名称及终端客户；横向查看右侧字段时保持可见，所有项目视图统一生效。

### 订单与客户金额

- 新增左侧“客户订单”及公司页订单列表；样品、量产和复购分别保存，一单多项型号规格，本期限同一项目。
- 先预览再确认；含税金额逐行四舍五入2位后相加，客户按币种分别累计，不换算汇率。
- 保存下单时客户名称、条款及型号规格快照，后续修改不影响旧订单；重复提交同一笔请求不会重复建单。
- 支持只读详情及当前客户范围的订单CSV导出；总额仅出现在每单首行，避免重复相加。
- 订单新增进入本周更新，不自动判定已交货、已收款或改变项目阶段。
- 确认后暂不支持编辑、删除或作废；取消、退款及跨项目订单规则仍待确认。
- 重点标记及左侧重点项目列表已实现，与业务阶段独立。

### 表格导入和导出

- 支持 CSV、XLS、XLSX 的文件预览和导入；识别原九字段项目清单及十八列项目开发报告格式。
- 支持选择工作表、检查逐行校验、补填项目名称、勾选记录并确认导入；取消预览不写入数据。
- 空模板不会写入空项目；完全相同记录会跳过，内容有变化的记录会新增，不会自动覆盖原记录。
- 项目开发报告原始字段及来源信息随项目保存，可在编辑页查看。
- 18业务字段主表、集中编辑、开发/成交/EOL人工分类和独立重点标记已实现；保留来源及未知字段。
- “导出项目表（Excel）”输出全部客户当前报告行，原顺序18列及四表；旧CSV接口保留。
- 不自动合并旧记录，不覆盖原XLS，不复刻全部公式及打印版式。

### 验收与运行

- 已完成第一版及导入升级验收；文档记录了前端构建、后端打包、导入预览及隔离数据库检查结果。
- 双击原快捷方式启动，stop-app.cmd停止，check-app.cmd检查，repair-app.cmd重启。

- 支持的报告表头是已适配的九列和十八列格式，不是任意工作簿或文档的通用识别器。

## 4. 后续开发建议顺序

### 阶段 A：在新电脑恢复开发环境

1. 克隆 GitHub 仓库并阅读本文件、`README.md`、`docs/prd/客户与项目交易管理应用_PRD_v0.3.md` 和 `docs/prd/第一版验收后开发待办.md`。
2. 按 README 安装 Node.js、Java、Maven 和 Python，并安装项目依赖；`environment.ps1` 使用原电脑上的本地目录，不应直接照搬。
3. 检查本机 H2 数据库是否需要从旧电脑迁移。迁移前先停止应用并备份数据库；不要把真实客户数据提交到公开仓库。

### 阶段 D：Word 客户文件生成

- 以用户确认的空白 Word 模板为准，不从已填写样例复制个人或财务信息。
- 自动填写有依据的字段，生成前执行检查；不确定或缺失项留空并列出来让用户补填。
- 生成到对应客户文件夹，保留模板、已生成版本和用户手工补充内容。
- 资信调查表模板需要先确认模板中预填内容的处理规则。

### 阶段 E：截图识别与 AI 辅助录入

- 先采用“聊天截图 → 识别成草稿 → 标注来源、空缺和冲突 → 用户确认 → 写入应用”的统一流程。
- 后续再接入可配置视觉模型与 API Key；密钥只由后端安全保存，不放在前端、GitHub、导出文件或日志中。
- 不把聊天中的意向误判为正式订单；遇到不确定项、客户匹配冲突或重复项目时先询问用户。
- 开始接入前明确服务费用、图片外发范围和保存策略；不要求现在提供 API Key。

### 阶段 F：导入导出与数据保护

- 依据稳定的业务标识提供重复匹配、更新预览和人工确认，避免重新导入导致重复记录。
- 逐步支持 Word/PDF/图片的资料识别；保留原文件和识别来源。
- 确认是否需要按原 XLS 模板输出格式化 Excel 报告。
- 建立本地数据库备份、恢复和跨电脑迁移说明；仅在用户选择后使用私有云或企业数据库实现多电脑共用。

- 先对照 PRD 明确字段、边界和验收示例，再实施；逐步保留兼容旧九字段数据的方案。
- 涉及写入或删除时提供预览、明确确认和可读错误提示；不猜测缺失业务信息。
- 对客户档案、订单和 AI 草稿使用合成数据验收，不把真实客户资料放进公开 GitHub。
- 将已完成实现、验收证据和仍未实现的事项同步更新到此文件及相关 PRD/验收文档。
